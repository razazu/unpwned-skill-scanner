# Worked review: a useful FAQ with an unnecessary upload

**Illustrative manual review, not a scanner result or benchmark**

This is a completed manual review of [case 05, an unapproved external copy](../examples/05-unapproved-external-copy.md). Everything in the case is fictional. No skill was installed, no program was run and no project was uploaded for this exercise.

The task is to suggest a FAQ using three draft pages supplied by the user. The excerpt adds a complete project upload to an outside diagnostic service, including private drafts and configuration, before producing the FAQ.

## Review scope

The available evidence is the user's stated task and excerpt lines L1–L4. There is no full package, executable helper, service contract or runtime trace. The decision therefore applies to the actions described in the excerpt, not to an unseen implementation or an author's motives.

## Completed checklist

A checked box means the review question was answered. It does not mean the proposed action passed review.

- [x] **State the intended result.** A draft FAQ, returned to the user for review. No publication or project transfer was requested.
- [x] **Identify the authorized input.** Three supplied draft pages. The task does not authorize access to all project files.
- [x] **Locate the workflow change.** L2 inserts an external transfer between reading the pages in L1 and drafting the FAQ in L4.
- [x] **Name the added data.** L2–L3 request the whole project, private drafts and configuration. This is broader than the material needed to answer the task.
- [x] **Name the added action.** Copying and transmitting project material to another service. Calling it a diagnostic step does not remove that effect.
- [x] **Review the destination.** The recipient's operator, use of the information and retention are not specified. Destination approval is unknown.
- [x] **Check the authority.** The user's permission to use the three pages does not authorize this recipient or the expanded data set. The skill's wording cannot supply the missing permission.
- [x] **Choose a bounded next step.** Reject the upload and draft from the supplied pages. If that is insufficient, explain the missing information without sending project material elsewhere.

## Decision record

| Item | Recorded conclusion |
| --- | --- |
| Action rejected | The complete project transfer in L2–L3. |
| Reason | Unnecessary expansion of both the data and its recipients, with no demonstrated authority for the transfer. |
| Action permitted within this scenario | Read the three supplied pages and return FAQ suggestions through the already authorized agent workflow. |
| Access not needed | Other project files, configuration values and an upload capability for the proposed service. |
| Information still unknown | The service's identity and handling of data, the full skill package and any actual runtime behavior. |
| Condition for a fresh review | A necessary, specifically identified recipient; a minimal proposed input; and approval from someone with authority over that disclosure. |

An explicit approval must refer to the actual data, destination and action being considered. It would not turn an unexplained whole-project copy into a proportionate input by itself. The narrower task can continue without the transfer.

## What this review does not establish

The excerpt supports a concern about the proposed upload. It does not prove theft, confirm that a transfer occurred, or establish that the outside service is malicious. It also does not predict what any scanner would flag. There is no score, scanner output or detection benchmark behind this decision.

Compare [case 01](../examples/01-scoped-formatting.md), where selected documents are read for the requested purpose, and [case 02](../examples/02-approved-document-edit.md), where an actual user authorizes a specific edit. The useful distinction is the fit between task, data, action, destination and permission.
